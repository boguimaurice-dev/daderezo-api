📘 Guide officiel · Installation & Utilisation v4.8

DADEREZO — Guide technique d'installation et de utilisation

Plateforme SaaS multi-agents de supervision, de sécurité et de pilotage actif des réseaux locaux par IA. Suivez ce guide pour déployer, configurer et exploiter l'architecture complète en 30 minutes.

📥 Installation pas à pas 🛠️ Comment utiliser 🌐 Site officiel

1 · Présentation

DADEREZO v4.8 est une plateforme multi-agents conçue pour superviser, auditer et piloter des réseaux locaux (LAN & WAN, Multi-Box Wi-Fi, Hub Multimédia) — par la voix et l'écrit — grâce à 5 agents IA spécialisés.

  • 5 agents IA : SENTINEL-SEC, TOPO-SCAN, DIAG-NET, NET-CONTROL, MEDIA-HUB
  • Contrôle Internet granulaire : Box Principale / Sous-réseau CIDR / Appareil précis
  • Optimisation Multi-Box : Wi-Fi, QoS, DNS, MTU
  • Partage multimédia : Cloud + LAN (même sans Internet)
  • Isolation multi-tenant privée : clés sonde et espaces organisateurs
  • IA générative** : DeepSeek ReAct + Voice & Voice (TTS/ASR)

🏢 Public cible

Écoles, communautés, centres de santé, PME multi-sites, opérateurs (rentabilité), associations.

⚙️ Stack technique

FastAPI (Python), Supabase PostgreSQL 17, DeepSeek LLM, Contabo VPS (optionnel), Vercel (API SaaS), PWA offline.

2 · Architecture

5 agents IA coordonnés par un orchestrateur, orbitant autour d'un Poste Superviseur et d'une sonde terrain. La télémétrie reste isolée par clé privée organisationnelle.

1 ├── agent_client.py (--task-poll 5 --media-port 8090) 2 ├── storage.py (Supabase PG17 / Storage / SQLite) 3 ├── agent_engine.py (5 Agents + Audit + HITL) 4 │ ├── SENTINEL-SEC (Anti-injection & Isolation) 5 │ ├── TOPO-SCAN (Matrice LAN vs Internet) 6 │ ├── DIAG-NET (Corrélation FAI & Ticket) 7 │ ├── NET-CONTROL (Switches Internet 3 niveaux) 8 │ └── MEDIA-HUB (Docs/Images/Audios/Vidéos) 9 └── api.py (Frontend, Auth, API REST, Auth)

🗺️ TOPO-SCAN

Matrice LAN vs Internet, latence, analyse de la topologie et des alertes.

📡 DIAG-NET

Corrélation FAI vs LAN, diagnostic, tickets opérateurs, détection de pannes.

⚡ NET-CONTROL

Interrupteurs Internet (Box/Subnet/Zone/Device), optimisation box, reboot.

🎬 MEDIA-HUB

Partage de documents, images, audios, vidéos sur LAN et Cloud.

3 · Installation

Trois parcours selon votre contexte. La méthode Vercel + Supabase est recommandée pour un déploiement 24/7 en production.

Étape 1 · Local
Tester l'API localement
Lancement rapide pour validation de l'architecture et des agents.
Étape 2 · Production
Déployement Vercel + Supabase
Déploiement SaaS type production, 24/7, multi-tenant avec clés individuelles.
Étape 3 · Sonde terrain
Liaison sonde
Agent Python (agent_client.py) sur chaque poste requis, sans dépendance lourde.
01

🚀 Démarrage rapide (local)

# 1. Installer les dépendances
pip install -r requirements.txt

# 2. Lancer l'API et le superviseur
uvicorn api:app --host 0.0.0.0 --port 8000
  • Accueil & Démo Live : /
  • Poste Superviseur : /ui
  • État JSON : /health
  • Docs OpenAPI : /docs
02

☁️ Production (Vercel + Supabase)

# 1. Créer un projet Supabase PostgreSQL 17
# 2. Importer le schéma Supabase (agents, probes, devices, alerts, state, tasks, agent_sessions, agent_audit_logs, human_approvals)

# 2. Importer le dépôt sur Vercel
#    GitHub > daderezo-api > Vercel → configurez les variables :
#      SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, DADEREZO_API_KEY

# 3. Déployer : l'API communique en HTTPS pur (port 443)

Variables recommandées : SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, DADEREZO_API_KEY, GROQ_API_KEY (optionnel), OPENAI_API_KEY (optionnel).

03

📡 Connecter la sonde terrain

python agent_client.py \
  --api https://votre-domaine.vercel.app \
  --agent ma-communaute \
  --nom "Communauté de Test" \
  --task-poll 5 \
  --media-port 8090
  • Aucune librairie Python externe sur la sonde
  • Hôte actif 24/7 (box, PC, Raspberry Pi…)
  • Clé sonde dédiée révocable par organisation
  • Hub multimédia LAN : --media-port 8090

4 · Configuration

Le fichier .env ou les variables d'environnement du déploiement définissent le comportement de l'API, des agents et du superviseur.

Variables d'environnement (production)

1 # ── Base de données (Supabase PostgreSQL 17) ──────────────── 2 SUPABASE_URL=https://<votre-ref>.supabase.co 3 SUPABASE_SERVICE_ROLE_KEY=<clé service_role> 4 # ── Sécurité API ──────────────────────────────────────────────── 5 DADEREZO_API_KEY=<votre_clé_secrète> 6 DADEREZO_AUTH_SECRET=<clé HMAC JWT (obligatoire) 7 # ── Cerveau LLM (DeepSeek) ───────────────────────────────────── 8 DEEPSEEK_API_KEY=<votre_clé_deepseek> 9 DADEREZO_LLM_MODEL=deepseek-chat 10 # ── Gestionnaire de contenu (optionnel) ──────────────────────── 11 DADEREZO_LLM_PROVIDER=deepseek 12 DADEREZO_SECRET_KEY=<clé secrète de session>

5 · Utilisation

Le Poste Superviseur Général offre un pilotage écrit et vocal, avec acceptation manuelle (HITL) pour les actions critiques.

1

Connexion & espace privé

  • Ouvrir http://localhost:8000/ui (ou /ui?auth=1)
  • Créer ou se connecter à son Espace Privé (email + mot de passe + 2FA TOTP)
  • Recevoir la clé sonde dédiée dzk_... pour chaque sonde
2

Pilotage écrit & vocal

  • Taper ou dicter des commandes : « Coupe Internet sur la zone Visiteurs »
  • Aucune écriture de règles nécessaire : l'agent décompose la demande
  • Validation manuelle (HITL) pour les actions critiques : reboot, coupure, sync
3

Monitoring & Alertes

  • État instantané : appareils, zones, interférence Wi-Fi
  • Alertes temps réel (propriétaire, Slack, Discord, Telegram, WhatsApp)
  • Journal d'audit et traces de décision (audit log)
4

Gestion multimédia (LAN)

  • Hub multimédia HTTP sur --media-port 8090
  • Accessible sur le LAN même sans Internet
  • Partage de documents, images, sons, vidéos par zone

7 · Sécurité

DADEREZO intègre des contrôles de sécurité natifs : isolation multi-tenant, 2FA, autorisation d'action, journal d'audit et clés de session révocables.

🔑 Isolation multi-tenant

Chaque organisation dispose de clés privées dédiées (dzk_…, dzt_… signées HMAC-SHA256). Les espaces privés sont fermés au public.

🛡️ 2FA TOTP RFC 6238

Authentification à deux facteurs par application (Google/Microsoft Authenticator). Vérification en temps réel, tolérance ±30 secondes.

🔌 Validation (HITL)

Les actions critiques (coupe Internet, reboot, sync) nécessitent une validation manuelle de l'administrateur.

📜 Journal d'audit

Toutes les actions sont tracées : identité, heure, contexte, décision. Utilisé pour les révocations et les audits.

🚫 Anti-injection

SENTINEL-SEC vérifie les politiques de sécurité et isole les tenants privés, empêchant les injections de prompt.

🧹 Rate limiting

Fenêtre glissante anti-bruteforce (5 tentatives / 15 min) sur les endpoints /auth/*, avec verrouillage et blacklistage.

8 · FAQ

Quelle est la différence entre /ui et /app ?
Les deux point vers le même Poste Superviseur Général. /ui est l'ancien nom, /app est la navigation plus moderne.
Dois-je avoir une clé sonde pour chaque poste ?
Oui. Chaque sonde reçoit une clé dédiée dzk_…, révocable à tout moment, garantissant l'isolement de chaque environnement.
Quelle est la latence des commandes ?
En général < 200 ms (Box locale ~1.2 ms, sortie FAI ~32 ms). La latence dépend de la qualité du lien entre la sonde et l'API.
Puis-je fonctionner hors ligne ?
Oui. L'API et le Hub Multimédia LAN restent accessibles via le PWA installable et le mode offline résilient (cache Service Worker).
Qui héberge les données réelles ?
Vous, dans votre Supabase PostgreSQL 17. L'API communique uniquement en HTTPS (port 443) et ne garde aucune donnée en dur.
Le player vocal est-il vraiment fonctionnel ?
Oui : synthèse vocale (TTS) et reconnaissance vocale (ASR) en français, turn-taking, barge-in et boucle vocale natifs.
Et les incidents de sécurité ?
Tout est tracé dans l'audit log. Les clés sonde sont révocables, le mode activité est activé par défaut (mode actif), et le tout est sous 2FA.
